# dsh-pet-mail · DSH 原生插件（二期草案）

> 状态：**设计稿**——等待 DSH（DeepSeek）确认插件体系细节后动工。
> 背景与动机见下一节（原设计提案为项目内部文档，未随仓库发布）。

## 为什么要有这个插件

一期的事件源（小狐娘侧进程命令行探测）是「通用 hack」：扫 `zcode.cjs -p` 进程。
它有效，但 DSH 作为**派单的发起方**，天然知道每次派单的 prompt/cwd/mode/session，
还知道任务取消与失败——原生信号比进程猜测干净得多，且能覆盖探测天然看不到的事件
（如 DSH 主动取消、派单前校验失败）。

## 职责边界（重要）

| 归插件 | 不归插件 |
|--------|----------|
| 派单事件源（原生回调 → 写邮件 + 任务表） | 桌宠本体（动画/气泡永远属于各桌宠自己） |
| 信箱设施（目录管理、registry 读写 API） | 派单逻辑本身（插件只旁观，绝不阻塞/修改派单） |
| 设置页（角色/路由管理，替代大肥鱼设置页里的临时版） | MCP 桥（桥保持无状态） |

## 事件契约（对 pet-mail 协议的输出承诺）

插件对信箱的输出与一期事件源**逐字节兼容**：

1. `zcode_run` 派单开始 →
   - 更新 `state/headless-tasks.json`（active/count/tasks/updatedAt）；
   - 按 registry 路由写 `mails/pending/` 邮件（kind=`dsh-dispatch`，body=任务摘要+mode）。
2. 派单结束（完成/失败/取消）→ 更新任务表；`task-done`/`task-failed` 事件为一期预留。
3. 任何异常**不得影响派单本身**：通知全部 try/catch 吞掉并记日志。
4. registry 每次事件现读（设置改完即生效），不缓存。
